# Proposed title

Add durable harness experiments and multi-tenant optimization service

# Proposed description

The original harness needs a coding agent to drive a shared-file loop. This adds a FastAPI/PostgreSQL service that queues sandboxed TerminalBench work, proposes versioned harness changes, and preserves the full history. Experiments now compare multi-file packages with independent tools, context and skill hypotheses; a worker crash retries an interrupted task while keeping completed trials.

- Immutable packages contain Python modules, skill procedures/resources and configuration, with parent lineage, file diffs, hashes and exact runnable source. Proposed code loads only inside Docker sandboxes.
- Durable experiments freeze candidate versions, model/budget profiles, development/held-out splits and repetitions. Each task trial uses leased, fenced PostgreSQL jobs. Cancellation covers unfinished children; tenant/owner checks cover versions, experiments, jobs and evidence.
- A shared admission pool bounds work across workers and retains reservations until cleanup. A separate lease watchdog stops execution during blocked heartbeats. The task supervisor records exits/timeouts independently of agent metadata. Shared task-cache copies use locking and atomic publication so concurrent readers and killed writers cannot expose a partial task.
- Asynchronous package proposals retain validation and failure evidence. Held-out evidence is rejected as proposal input. Exploration evaluates the frozen candidate set; promotion remains separate. The original iterative optimization endpoint retains strict improvement/no-regression acceptance.
- Automatic optimization runs add a durable multi-round controller: baseline, independent package proposals, fresh incumbent/candidate comparisons, no-regression selection, bounded continuation and final held-out checks. Round decisions and failed proposals feed subsequent development proposals; held-out results never do. Control flow is an additional mutation dimension. The controller creates children and records transitions in one transaction, and occupies no sandbox slot while waiting.
- Compose setup, migrations, locked dependencies, CI, the resumable `test_client.py --experiment` workflow, and operator inspection of actual context/skill/tool use are documented. The original CLI is preserved.

Validation: **67 PostgreSQL tests pass**, including all three client workflows over real HTTP, multi-round selection, controller rollback/concurrency and failure isolation, experiment resume/idempotency, cross-tenant access, held-out gating, proposal checkpoints, fencing, capacity and final-child aggregation recovery. Offline Docker checks load package helpers/skills and reject crashing code, broken tool history and an infinite loop. The real worker failure drill used four processes with two slots: killed worker recovered, stale write rejected, completed history preserved, cancellation and task interruption handled, zero remaining containers/reservations. Peak observed concurrency was two. Its final 30.95-second synthetic workload is infrastructure evidence, not production benchmark throughput. The cache test reproduced a partial read without protection and passed concurrent-reader/killed-writer recovery with the fix; a real Harbor smoke passed through the final launcher.

The controlled package comparison completed **36 real trials in 30m11s**, each on its first attempt with zero runner errors. GPT-5.4 generated the packages; every trial used the same Astra Responses profile. Development scores: baseline **6/6**, skills **6/6**, tools **5/6**, context **5/6**; all versions passed **3/3** designated held-out tasks. No pass-rate improvement or automatic promotion. All six proposal attempts, reviewed-out versions and scored failures are retained. Actual requests confirm 39 structured status results, eight compacted outputs and skill loading in all nine skills trials. The report includes exact packages, hashes, task source revisions, full iteration history, timing, usage and small-sample limitations.

Earlier live evidence includes a full ten-task automatic code optimization that rejected a regressing candidate, a repeated 46-trial comparison whose development gain did not carry over to held-out tasks, and the unchanged-policy Astra baseline at 7/10. These historical reports remain available; no general performance improvement is claimed.

Scope limits: one shared Docker engine/artifact volume, no multi-host placement or HA, scoped-key inference proxy, statistical promotion, or production VM isolation. E2B is not implemented. The historical operator comparison CLI bypasses managed admission and should not run concurrently with worker experiments.
